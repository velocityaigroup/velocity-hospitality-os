# R4 — Running the provided open-weights model, step by step
**Goal:** Qwen 3.6 27B on the Impala gateway answering through Velocity's agents on Firefly Estate
Bequia's own knowledge, with screenshots a judge can open.
**Time:** about 15 minutes, most of it waiting for you to find the key.
**Windows/PowerShell first, because that is what you are on. bash equivalents at the end.**

---

## Step 1 — Get the three values from the Builder Portal

Open **os.futurecaribbean.com/builder** → **Resources** → look for **"Your gateway & key"**.

You need three things:

| | Value |
|---|---|
| Gateway URL | `https://ht.getimpala.ai/v1` |
| Model name | `qwen3.6-27b` |
| API key | your team's virtual key, starts with `sk-` |

The first two are already documented in `docs/impala-connect.md`. **The key is the only thing you
actually have to go and find.** If you cannot see it in Resources, ask in the Discord
(discord.gg/nF3FSA6Rqb) or email the organisers — teams get one per team, and this is the single
thing blocking the highest-value item on your board.

**Never paste the key into a file that gets committed.** It only ever lives in your shell session.

## Step 2 — Set the five environment variables

Open PowerShell, go to the repo, and paste this — replacing the last line with your real key:

```powershell
cd "D:\Project\Velocity AI Group\04_Products\Velocity-Hospitality-OS\velocity-hospitality-os"

$env:VHOS_LLM_BACKEND      = "openweights"
$env:VHOS_EMBED_BACKEND    = "local"
$env:VHOS_OPENWEIGHTS_URL  = "https://ht.getimpala.ai/v1"
$env:VHOS_OPENWEIGHTS_MODEL= "qwen3.6-27b"
$env:VHOS_OPENWEIGHTS_API_KEY = "sk-PASTE-YOUR-TEAM-KEY-HERE"
```

Two things worth understanding rather than just pasting:

- `VHOS_EMBED_BACKEND=local` keeps embeddings offline. You are swapping the **answering** model, not
  the retriever. Nothing else needs provisioning, and the retrieval metric stays comparable.
- These are **session** variables. Close PowerShell and they are gone — which is exactly what you
  want for a secret. Every new window needs them again.

Sanity check before going further:

```powershell
python -c "import sys; sys.path.insert(0,'src'); from velocity_hos.config import settings; print(settings.llm_backend, settings.openweights_model, bool(settings.openweights_api_key))"
```

Expect: `openweights qwen3.6-27b True`. If you get `local`, the variables did not take — you are
probably in a different window from the one you set them in.

## Step 3 — Prove it connects (30 seconds)

```powershell
python scripts/openweights_smoketest.py
```

This is the minimal handshake — one question against a two-line SOP. Green means the gateway is
reachable, the key works and the model name is right. If it fails, the script prints a four-point
checklist; the usual culprit is a typo in the model name.

**Do not screenshot this one.** It is a connectivity check, not evidence.

## If it will not connect

| Symptom | Likely cause |
|---|---|
| `VHOS_LLM_BACKEND is not 'openweights'` | Variables set in a different PowerShell window. Set them again in the one you are running from. |
| Connection refused / timeout | Gateway URL wrong, or you are behind a network that blocks it. Check `https://ht.getimpala.ai/v1` exactly, including `/v1`. |
| 401 / 403 | Key wrong, expired, or not yet issued to your team. |
| 404 on the model | Model name mismatch. It is `qwen3.6-27b`, not the HuggingFace-style `Qwen/Qwen3.6-27B-Instruct` (that string is only the default for a self-hosted vLLM). |
| Answers arrive with visible `<think>` reasoning | `VHOS_OPENWEIGHTS_NO_THINK` defaults to on and strips it. If you see it anyway, set `$env:VHOS_OPENWEIGHTS_NO_THINK="1"` explicitly. |

Two or three failed attempts and no key in the portal → stop and ask the organisers. Do not burn an
evening on it; the key is theirs to issue.
